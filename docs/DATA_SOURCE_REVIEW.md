# 武汉多源建筑资料核查

核查日期：2026-10-28。范围只涉及现有汉口试验区的数据补强，不讨论扩区。本轮核对官方论文、作者发布页、文件索引和许可元数据；没有下载大型建筑包，也没有改变运行场景。

## 关键判断

武汉拥有专业测绘资料，但不等于这些资料可以公开下载、直接用于项目。官方资料披露全市激光雷达建筑点云、0.5m DEM/DSM 和道路精细测绘成果。当前问题是可获取与可使用的数据，而不能概括为城市本身没有数据。

来源：[武汉市自然资源和城乡建设局，2026-01-07](https://zrzyhcxjs.wuhan.gov.cn/zwdt/gzdt/202601/t20260108_2708183.shtml)。另有[武汉市数据局发布的武昌重点区域三维地图交易案例](https://home.wuhan.gov.cn/sjjczlwl/yssc/202608/t20260825_2838368.shtml)，说明可申请或采购的产品路径存在；不证明有当前汉口样区的现成开放包，也不作为本轮扩区建议。

## 候选源与优先级

### 1. 3D-GloBFP：第一批实测候选

提供建筑多边形及以米计的模型估计高度，参考年份 2020。研究在不同验证区的误差并不一致，不能把整体论文指标当作武汉本地精度。发布记录为 CC BY 4.0；融合时还需保留其原始几何来源记录。

旧的亚洲记录中 China.rar 为 15,701,271,640 bytes，约15.7GB。**新版已经可以按网格下载，不必先下载整个中国包**。通过作者 Zenodo 下载索引与 Figshare 官方 API 已定位包含当前试验区的文件：

- 记录：https://figshare.com/articles/dataset/28906499 ，当前 version 3（2025-11-01）。
- 文件：`2322_113.75_30.0_115.0_31.25_hubeiCN.zip`
- 包围框：113.75–115.0°E、30.0–31.25°N，包含现有武汉样区。
- 大小：135,482,231 bytes，约135MB。
- 单文件下载：https://ndownloader.figshare.com/files/54107378
- 元数据核查：https://api.figshare.com/v2/articles/28906499

这里只证明发布包空间范围覆盖武汉，**尚未打开该包验证样区逐栋覆盖率、属性字段、坐标系和高度质量**。下一步下载后先做小范围匹配和审计，不直接覆盖现有高度。

官方来源：[论文](https://essd.copernicus.org/articles/16/5357/2024/)、[新版索引](https://zenodo.org/records/15487006)、[分块链接](https://zenodo.org/records/15487006/files/data_links.txt?download=1)、[命名说明](https://zenodo.org/records/15487006/files/readme.txt?download=1)。

### 2. GABLE：单栋高度和屋顶分类候选

作者说明其产品包含紧凑屋顶多边形、估计高度及 12 类屋顶类别，官方 README 已列湖北包。**屋顶类别不是住宅／商业等用途类别**，不能据此自动替代用途资料。

- 官方仓库：https://github.com/AICyberTeam/GABLE
- 湖北下载：https://pan.baidu.com/s/1c-pcXdtZTTRLmfT3GACKmw ，提取码 `9aps`。
- 官方提示应使用 2024-07-29 起修正后的数据。
- 仓库 LICENSE 为 MIT，内容明确针对 Software；网盘包内是否附单独的数据许可、年份和字段说明仍待核对，不能只凭代码许可作出数据商业使用承诺。
- 本轮未能通过网页工具读取网盘文件列表，尚未取得湖北数据本体。

GABLE 对细分屋顶与高度的价值可能高于继续补普通轮廓，但需检查屋顶投影与地面轮廓的差别，避免错位叠楼。

### 3. CNBH-10m：高度约束与交叉检查

2020 年中国 10m 建筑高度估计栅格，作者 Zenodo 记录可直接下载，API 许可字段为 `cc-by-4.0`。这是每像元的估计值，**10m 空间分辨率不是10m高度精度，也不等于单栋真实高度**。

- 当前记录：https://zenodo.org/records/7923866
- API：https://zenodo.org/api/records/7923866
- 索引中可见 `CNBH10m_X113Y31.tif`（82,283,483 bytes）、`CNBH10m_X115Y31.tif`（95,324,695 bytes）。未读取 GeoTIFF 地理变换，不能仅凭文件名确定武汉应取哪张。

适合对建筑平面覆盖像元取稳健统计、检查街区高度分布，作为模型高度的交叉检查及缺失时的后备。薄小建筑、高低楼混合像元、院落和裙房塔楼会有混合效应，不能只采中心点就当作楼高。

### 4. OpenBuildingMap：降低优先级

官网介绍全球整合 OSM、Google、Microsoft，并按 OSM/POI/用地和 GHSL 补属性，ODbL。其论文明确指出中国等地是覆盖薄弱区；发布版本在这些地区主要依赖 OSM，而不是额外拥有完整中国建筑底图。缺高时用 GHSL 的高度类别估层数，对较高建筑也存在明显限制。

我们现有 OSM + Overture 已解决相当部分轮廓补漏。OBM 可借鉴其语义规则或抽样对照，但目前不应作为“全球覆盖，所以武汉会更精细”的主方案。微软现有发布会更新，具体武汉覆盖仍需按当前索引核查，论文的历史覆盖结论不能自动当作2026年微软索引的现状。

来源：[官网](https://www.openbuildingmap.org/)、[作者论文](https://www.nature.com/articles/s41597-025-06132-z)。

### 5. GlobalBuildingAtlas：可研究，但许可分层

其作者明确将 ODbL 轮廓、CC BY-NC 4.0 轮廓／LoD1，以及 CC BY-NC 4.0 高度图分开。**可用的 ODbL 轮廓不意味着高度也成为 ODbL**。模型存在误差，WFS 查看器也明确不供自动抓取和批量下载。应使用正式发布包，非商业研究及产品用途分别处理；不混入当前默认可分发数据层。

来源：https://github.com/zhu-xlab/GlobalBuildingAtlas

### 6. 微软 Global ML / 武大 CBF：轮廓补漏备选

微软当前官方发布许可是 CDLA Permissive 2.0，具有部分地区的估计高度，但全球命名与高度字段的存在不能证明武汉覆盖。应先查发布索引与已有 Overture 的重复来源，避免重复导入同一批模型结果。

CBF 官方搜索摘要确认是由2019–2020影像生成的中国亚米级足迹；本轮作者页面连续返回访问错误，未重新核实直接下载与授权条件。不能把此前聊天中提到的“联系团队”替代为已核实许可，也不将其作为马上能取得的武汉高度包。

来源：https://github.com/microsoft/GlobalMLBuildingFootprints 、https://irsip.whu.edu.cn/resv2/GBD_data/cbf_show.php 。

## 还需补哪些资料

- **用途／商铺**：继续挖掘 OSM 的建筑、POI 和关系；Overture Places 是独立图层（现有项目只取了 Buildings），可以提取现有样区检查其实际增量、关闭店铺和位置误差。不能把企业位置当作整栋用途或精确店面入口。官方说明：https://docs.overturemaps.org/guides/places/ 。
- **历史立面**：遥感轮廓和高度包不会直接提供窗数、柱式、檐口和首层。应建立逐建筑参考目录，利用公开介绍、可使用照片、保护图则或申请取得的测绘资料提取参数。用途、年代、屋顶类别、立面风格分开记录。
- **路灯／信号／横道／人行道**：建筑数据集不提供这些要素的完整库存。继续导入真实交通设施资料，或基于经许可影像及现场照片核对；缺失时生成规则应有推断标记和空间约束。上一轮26个信号节点来自已有PBF，证明导入质量也重要，不能把全部差距归因于源覆盖。

## 融合方案

1. 保留稳定武汉对象 ID、当前源轮廓与坐标框架。新数据先作为独立候选层，不直接替换场景。
2. 用轮廓重叠、面积比例、中心距离、名称及建筑分部建立匹配，分别记录一对一、一对多、多对一与未匹配。注意年份变化、屋顶投影、源坐标系和地面轮廓差异。
3. 高度优先级：核实资料／测量 > 有来源的层数换算 > 经验证的单栋遥感高度 > 栅格约束 > 类型推断。两份模型有冲突时不简单平均，共享原始数据的结果也不当成独立投票。
4. 裙房和塔楼分别匹配，避免把整片商业平面拉成塔楼高度；照片立面不改变源地理位置。
5. 为每条结果保留来源、版本、参考年份、方法、匹配质量、单位、许可、置信度与备选值。遥感估计始终标为估计。
6. 先在现有样区选取有独立资料的建筑样本，比较覆盖率、匹配率、明显错配、低／中／高层误差以及沿街视角，再确定主候选源。不能以属性填充率或“看起来高低丰富”作为精度证明。

建议第一批比较 3D-GloBFP 与 GABLE，并以 CNBH 作约束／交叉检查。已有文献高度与层数先保留，不让候选模型覆盖它们。此结论是优先级建议，尚不是三份数据已被下载、匹配或接入的声明。
