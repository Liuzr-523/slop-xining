# 0.4.0：运行基础切换为台北

2026-10-28，按用户决定将台北作为后续武汉项目的运行与视觉基础。源码参考 revision `1d70708fc92a088b779c8c0e22677adb64966a1b`，完整参考克隆位于工作区 `reference-taipei`。上海阶段归档分支 `archive/shanghai-runtime-0.3.0` 指向 `edd8d59`。

## 整合边界

- `js/runtime/`：从台北移植的实际运行模块；当前 `index.html` 直接加载该目录下 `main.js`。
- `css/taipei-runtime.css`：上游布局，界面文字、字体回退与格式改为简体中文。
- `tools/build-runtime.py`：把现有武汉源层转换为台北 GEO 契约，维护道路节点 ID、方向、禁车步行段、多边形内院、分层建筑、来源与推断元信息。未虚构道路连通点。
- `js/runtime/landmarks.js`：将已制作的江汉关坐标与地面高程接口从 y=2 转为新系统 y=0；不含台北专用地标。
- `js/runtime/collision-footprint.js`：复用武汉已有多环碰撞，适配台北的法向／深度接口；保留裙房和塔楼垂直范围。
- `js/runtime/street-props.js`：台北候选与合批机制，接入已有武汉 SpatialPlacement。店招本轮采用贴墙横牌，避免直接外挑侵占道路；停车候选移至人行道且经过空间检查。
- 台北特定经纬度相机与远山、地标、垃圾车音乐已从武汉运行路径移除。车辆素材和通用建筑细节仍需本地化，不宣称已实景复原。

台北依赖集群光照模块，而原上海打包的 Three.js 不包含这两个 addon。补齐现有 vendored Three.js **同一 revision** `8d737d9ceb701eedff7bba3086cefcbfb7fea9c5` 的 `ClusteredLighting.js`、`ClusteredLightsNode.js`，更新 vendor 来源清单。仍使用本地依赖，不要求运行时 CDN。

## 显示高度

`city.json` 保留审计过的源记录。缺高占位不冒充来源；运行转换分别记录 sourceHeight、sourceHeightType、displayHeight、displayHeightSource、sourceId。`hankou-display-v1` 是按用途、面积、对象 ID 稳定种子形成的保守视觉规则，不是台北层数分布直接移植，也没有取得精确武汉楼高的含义。已有层数、源高度和文献资料优先。高楼裙房／塔身仍使用已经核对过的三层体量配方。

规则调节入口 `display_height()`；修改后 `npm run data:runtime`。要重新提取数据则 `npm run data:build`。此阶段仍需积累街区照片和可靠层数校准分布；不以丰富度代替准确度。

## 运行与验收

- 54 项 JavaScript + 13 项 Python 测试，源层道路／建筑空间审计，生产构建。
- 新增测试验证当前入口、源文件哈希、无台北地理、资料高度优先、推断多样性、塔楼分部、道路方向／步行禁车、院落碰撞。
- 浏览器加载、步行／汽车／飞行模式、地图搜索和武汉景点视角检查；截图位于忽略提交的 `output/playwright/taipei-base-*`。
- WebGPU 预编译和视角变化仍可能出现瞬时停顿；当前整体载入小范围并做合批与距离裁剪，后续扩区前需补流式策略。旧上海测试和模块被保留作回归与迁移参考，不能把旧测试通过理解为新系统所有功能都已覆盖。

需要继续解决：显示高度校准、汉口建筑细节与更精准店招、桥隧高程、数据边缘与远景、更多已核实地标。当前没有承诺全市流式漫游或精确街景复原。

发布包（本地 4187）实测：江汉路步行输入产生超过 1m 位移，汽车／直升机切换成功，地图搜索“江汉关”定位到源坐标；运行错误 0。当前候选检查接受 2,369 棵树、717 盏路灯和 408 个停放踏板车，剩余规则冲突 0；212 条贴墙招牌，图集中 12 个源名称。以上是程序生成记录，均非实测设施数量。
