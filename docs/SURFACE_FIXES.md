# 0.5.1 江面、坡面与桥面修复

用户反馈：长江大桥／南岸嘴江面出现绿色矩形，龟山汉阳桥头车辆钻地，桥中间横向偏移会掉落。问题来自生成与接触逻辑，不把它们归结为原始DEM误差。

## 复现与原因

- 原buildHills把含高程的400×400m整块网格画成草地，包括位于江面上且高度为零的外围格子。因此有明显矩形压住水面。
- 原源层道路/地形采样为双线性，显示面又按50m多边形三角化，两者不是相同的几何表面。在世界坐标(-1233.33,2933.33)附近，旧可见面7.33m，接触采样2.44m，差约4.89m。车辆基准即使按采样贴地，也会被画面上的面盖住。
- 原大桥沿两条OSM单向车道分别建桥面、护栏并查询窄条支撑。横跨两幅车道时可能离开两条查询范围，支撑高度降到江底平面。0.5.0只验证了沿一条源线跨江，没有覆盖中缝和全宽移动。

## 修复

1. 删除独立整块山体覆盖层，只绘制经过真实陆地、水域和公园边界裁剪的地面层。保留原高程样本，山体不恢复成平地。
2. 地面图层按原25m采样网格的同一条对角线裁成三角面；Python建模、JS接触、建筑基础和人物使用相同的分片平面插值。坡面道路标线也贴到相同表面，人行道保留0.15m铺装高度。
3. 从相邻、长度相近的两幅桥梁道路生成共同边界和完整桥面；渲染与碰撞高度查询共享同一组三角面。保留两侧引道高程，移除内部护栏，只在外侧建护栏与实体碰撞。仍通过高度门限区分桥上、桥下。
4. 当前四组配对桥面包括长江大桥、江汉桥、晴川桥及武胜路高架桥；其余未配对高架沿用原处理。不更改水平坐标、距离和城市范围。

## 验证

- 新增鞍形高程、同一网格/对角线、桥梁全宽、弯道/坡度和桥下高度门限测试。
- 针对实际武汉数据，逐三角面检查两山可见地面和接触面的插值一致性；按每个站位横向5%至95%扫过配对桥面，确认连续支撑。
- 浏览器扫描实际地面网格约39.6万个三角面。与接触高程差不超过0.03m（含森林底层的材质偏移）；水中残留的三角形中心样本面积约0.017m²，是边缘浮点精度量级，不再存在整块绿色矩形。额外Hills整块网格不存在。
- 长江大桥正反方向反复变道各约2206m，横向偏移最高约3.81m；没有低于地形或失去桥面支撑。
- 龟山南路正反方向各约897m，没有钻地。
- 车辆持续朝外侧护栏行驶300个物理步，没有失去支撑或掉落。
- 上述车辆测试自动引导车头、实际调用同一车辆物理与碰撞逻辑，不冒充人工完整驾驶。详细JSON在acceptance/0.5.1；截图在忽略于Git的output/playwright/repair-*。

粗DEM、桥梁工程高程和简化外观仍存在精度限制。本轮修复接触和渲染的一致性，不宣称已取得精密测绘地形。
