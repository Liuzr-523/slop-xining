## 已完成

- 下载 Geofabrik 湖北 PBF，沿用上海 pyosmium 导入器，改为武汉坐标和试验范围。
- 输出上海运行时 schemaVersion 2、500m 建筑分块，不需要改写人物、车辆、相机或材质系统。
- 383 段道路，290 栋建筑体量，4 片水域，16 块；6 个命名道路目的地。
- 42 项默认测试与生产构建通过。WebGPU 运行首帧约 5.8 秒；本机观察约 60 FPS，采样 p50 16.7ms、p95 20.1ms；当次记录无运行错误。性能仅代表当前设备和初始视角。
- 修复上游非流式数据首次启动时小地图不绘制道路/水域的问题。

## 目前欠缺

OSM 建筑覆盖稀疏；284 栋高度估算，132 个矩形包围盒挤占道路的源建筑被排除。几何报告明确区分源轮廓与估算，不补虚构建筑。5 个导入源几何被跳过，尚需定位与核查。

平坦地形。桥隧和非零层级道路不开放。未接入武汉地铁、精细地标或网约车任务。上海地标构造器和通用地铁模块仍保留源代码，但武汉数据为空，不在场景中伪装使用。

下一步优先提高真实武汉数据覆盖、检查沿江空间、改进源建筑体量与道路宽度；之后再处理桥隧和扩大范围。暂不扩展玩法。

## 浏览器交互验收

# 0.2.1 · 统一空间规则与自动检查

按用户对自动化、工具化和路面障碍问题的反馈，增加公共规则，而非按个例手动挪物体。

- 保留普通建筑真实轮廓；在生成层关闭 3 处未确认的穿楼地面段（约 58.9m、14.5m 和 0.5m），原始源对象不修改。未来需确认它们是否为院内车道、门洞或数据错误。
- 路面、步行铺装与路肩避让建筑轮廓。独立复查 2,098 个普通建筑/地标轮廓，当前路面相交面积 0、中心线穿楼 0。
- 统一街具摆放器使用完整占地半径，并查询所有附近路段；同时避让建筑、水域、边界与已有街具，保留宽步行街的中央通道。
- 实际浏览器生成 149 处街具：34 普通路灯、16 树、6 树池、13 街景路灯、11 座椅、69 矮柱。拒绝 64 个建筑冲突、28 个车道冲突、17 个步行通道冲突、3 个街具冲突候选；生成规则剩余冲突 0。江汉关步行到达成功，无记录运行错误。
- 导入器与生成器共用区域配置，缓存包含范围检查；Overture 范围不足会停止，避免扩区时把缺资料误当成功。
- 新增 npm run verify：48 项 JavaScript 测试、4 项 Python 空间规则测试、生成数据独立审计、生产构建，均通过。

本轮没有扩展城市范围，也未解决楼高、真实高程和精细立面的资料缺口。纽约/上海/武汉生成方式对照和下一步工具化路线记录在 GENERATION_PIPELINE.md。
